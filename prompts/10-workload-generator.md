## Prompt

Read `CLAUDE.md` and the spec sections above. The product needs realistic, repeatable load: to collect
training data and to compare strategies fairly. Build a generator that produces **trace files**, and a
replayer that submits a trace with accurate timing.

### Trace format

`workloads/<name>.jsonl`: first line is a header
`{"name","pattern","seed","durationS","generatedAt","params"}`, then one line per task
`{"offsetMs","taskId","type","input","priority"}` sorted by `offsetMs`. Task ids are deterministic from
the seed so replays are comparable row by row.

### Generator (`predisched-client`, package `workload`)

`predisched workload generate --pattern <p> --seed <s> --duration <sec> [params] --out <file>`.
Patterns (spec §10.1), each a class implementing `ArrivalPattern`:

- `steady` — Poisson arrivals at `rate`.
- `bursty` — base rate with bursts of `burstRate` for `burstLen` seconds every `burstEvery` seconds.
- `periodic` — rate follows `base + amplitude·sin(2πt/period)` (non-homogeneous Poisson via thinning).
- `mixed` — any pattern plus a task-type mix (e.g. `cpu=0.5,matrix=0.2,sleep=0.3`) and input-size
  distributions per type (log-uniform ranges from config).
- `ramp` — rate rises linearly from `start` to `end` (useful for overload labels).

Priorities are drawn from a configurable distribution (default: 70% 1–4, 25% 5–8, 5% 9–10).

### Replayer

`predisched workload replay <file> --run-id <id> [--speed 1.0]`:

- Schedules each submission at `start + offsetMs/speed` using a `ScheduledExecutorService` with enough
  sender threads that a slow `SubmitTask` never delays the next one; reports schedule lag (P50/P99 of
  actual − intended submit time) and warns if P99 lag exceeds 20 ms.
- Tags every task with `run_id` (add `string run_id = 6;` to `TaskRequest`) so telemetry separates runs.
- Waits for all tasks to reach a terminal state (or `--timeout`) and prints a summary.

### Worker heterogeneity profiles

`configs/profiles/*.yaml` describing cluster shapes (`homogeneous-3`, `heterogeneous-3`: pool sizes
2/4/8 and `cpuLimitFactor` 0.5/1.0/1.0, `heterogeneous-5`). `scripts/start-cluster --profile <name>`
applies one. Record the profile name in the run.

### Tests

- Same seed → byte-identical trace file; different seed → different file.
- Pattern tests: measured arrival rate within 5% of the target over a long trace; bursty trace shows the
  bursts in the right windows; periodic trace's rate correlates with the sine (r > 0.9).
- `ReplayIT`: replaying a 30-second trace against an in-process cluster submits every task, with P99
  lag under 20 ms.

### Acceptance checks

```bash
mvn -q verify
java -jar predisched-client/target/predisched-client.jar workload generate --pattern bursty --seed 42 --duration 120 --out workloads/bursty-42.jsonl
java -jar predisched-client/target/predisched-client.jar workload replay workloads/bursty-42.jsonl --run-id smoke-1
```
