# Lab topic coverage

Each distributed-systems lab topic is implemented as a working part of PrediSched, not as a separate
program. This table is the map. The evidence columns are filled in by the prompt that builds each
part, with real commands and real measured output.

| # | Lab topic | Where it lives in the product | Why the product needs it | Built in | Demo command | Measured result |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | Client-server communication using RPC / RMI | `proto/task.proto` (`SchedulerService`), `proto/worker.proto` (`WorkerService`); `SchedulerServiceImpl`, `Dispatcher`, `WorkerServiceImpl`, `SchedulerClient` (`predisched` CLI) | Every hop between client, schedulers, workers and the model server | Prompt 01 (Java ↔ Java; Java ↔ Python in Prompt 13) | `scripts/start-cluster.ps1`, then `java -jar predisched-client/target/predisched-client.jar submit --type CPU_TASK --input 100000` + `watch <id>` | CPU/MATRIX/SLEEP tasks reach COMPLETED (e.g. `COMPLETED worker=worker-1 execMs=1 result=5000050000`); invalid tasks rejected with every violation; QUEUED-only cancel verified |
| 2 | Multithreading in a distributed system | `predisched-worker`: `ThreadPoolExecutor` (`worker-<id>-exec-<n>`), async `ExecuteTask`, `WorkerMetrics`; `predisched-scheduler`: `Dispatcher` sender pool, `WorkerRegistry`, `RegistryService`; `predisched-benchmark`: `pool-scaling` | Workers run many tasks at once; the scheduler serves many clients | Prompt 02 | `scripts/start-cluster.ps1` (1 scheduler + 3 workers), then `java -jar predisched-benchmark/target/predisched-benchmark.jar pool-scaling` | `ConcurrentSubmitIT`: 10×100 submits → 1000 COMPLETED, zero duplicates.
